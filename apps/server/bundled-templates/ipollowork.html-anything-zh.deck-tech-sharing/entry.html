deep-dive · 1 / 2

评测是管线的入口，
不是事后补考。

把评测前置到每次提交：任何 prompt 或模型变更，先过 golden set 回归门禁，再谈上线。不达标直接阻断合并，并附上逐条 diff 报告。

golden set · 500 条 regression gate ±2% 人工抽检 5%
eval_gate.py
def eval_gate(candidate, golden):
    report = run_eval(candidate, golden)
    if report.score < BASELINE - 0.02:
        raise RegressionError(report.diff)
    return report  # 通过门禁，进入灰度

# 每次 prompt 变更 = 一次 CI 评测
# 不达标 → 阻断合并 + diff 报告
#eval #ci04 / 08

deep-dive · 2 / 2

推理服务是一台
"偷算力"的调度器。

在线推理 = N 个推理 worker + 分级请求队列。空闲 worker 主动组批拉新请求，慢请求被隔离，不能拖垮整个在线池。

✦ continuous batching · 动态组批
✦ 优先级队列 · 交互 > 批处理
✦ 背压限流 @ 队列水位 80%
✦ 慢请求抢占 / 重试隔离

scheduler tick loop

1. 从优先队列取最高优请求
2. 组批：凑满 max_batch 或 50ms 超时
3. KV cache 不足 → 抢占最低优请求
4. 超时请求转异步队列，不占在线池
5. 队列空 → worker 挂起等唤醒

mini-eval.py · ~30 LOC

手写一个最小评测器。

mini-eval.py
import json
from dataclasses import dataclass

@dataclass
class Case:
    q: str
    expect: str

def main() -> None:
    cases = [Case(**c) for c in json.load(open("golden.jsonl"))]
    scores = [judge(c, chat(c.q)) for c in cases]  # LLM-as-judge 打分 0~1
    avg = sum(scores) / len(scores)
    print(f"score={avg:.3f} n={len(scores)}")
    assert avg >= 0.85, "回归门禁未通过"  # 就是这一行

// takeaways

三件事带回去。

1 · 评测先行

没有 golden set 的迭代都是盲人摸象。先建评测，再谈优化。

2 · 变更走门禁

prompt 和模型都是代码，过 CI 回归门禁才能上线。

3 · 在线服务要兜底

限流、抢占、降级三件套，让慢请求拖不垮整池。
